# Audit of the ChatGPT Parts D+G report (accessibility, offline, performance, testing, engineering), 2026-10-22

Raw report: `docs/24a-RESEARCH-DG-CHATGPT-RAW.md` (about 14,700 words). Verdict: **strong and mostly right; its best calls are also the right ones for our code** (nested lists not trees, native dialog, offline = pinned read-only, no WebCrypto-in-IndexedDB, own error table, small visual-regression set). It has **three real defects** (lint stack incompatible with our TypeScript 7, wrong Speed Insights claim, tabs assumed route-backed) and left several things UNVERIFIED that I resolved. I also audited our actual code against it (section 4): that found problems the report could not see.

## 2. Wrong, overstated or missing (my corrections)
1. **ESLint 10 + typescript-eslint is NOT usable with our stack.** Our repo runs TypeScript **7.0.2** (native compiler). `typescript-eslint` 8.72.0 (and `@typescript-eslint/parser`) declare `typescript >=4.8.4 <6.1.0`; TS 7.0 ships no programmatic API; a TS 7.1 beta (npm 2026-10-20) adds one, a stable 7.1 is reported for about 24 Nov 2026 (secondary sources only) and typescript-eslint support for it is UNVERIFIED (one secondary source says the request was closed "not planned" on 7.0 GA day). The report's "ADOPT ESLint 10 + typescript-eslint" ignores this.
2. **`eslint-plugin-jsx-a11y` is stale and incompatible**: latest 6.10.2 was published 2024-10-26 (about 24 months, breaks the 18-month rule) and its peer range stops at ESLint 9; the report recommended it without checking.
3. **Vercel Speed Insights on Hobby is much weaker than the report implies.** Free tier = Real Experience Score only, path/route counts for "Great"/"Needs improvement" entries, 24 h and 7 d ranges, 10,000 events per rolling 30 days shared across the team; hitting the limit pauses collection for at least 14 days. The LCP/INP/CLS breakdown needs Plus ($10/project on Pro). So real Core Web Vitals values need our own small RUM table (`web-vitals` 6.2.3).
4. **Tabs assumption**: the report assumes the organization tabs are route-backed and says to turn them into links. In our code they are **state-backed** (`setTab`) with `role="tab"`, so they are neither deep-linkable nor a complete APG tab widget (section 4).
5. Report said our CSS tokens were unavailable and only offered a candidate palette (its contrast numbers are correct: I recomputed all nine). The real tokens are in `parts/20-styles.tsx` and I audited them (section 4).
6. UNVERIFIED items resolved: typescript-eslint 8.72.0, eslint-plugin-react-hooks 7.1.1 (supports ESLint 10), knip 6.42.1, MCP Inspector 2.12.0, pa11y 10.0.0 (2026-10-09), `@sentry/browser` 11.8.0 (versions only; Sentry's free-tier/no-card terms still UNVERIFIED). Still UNVERIFIED: screen-reader behaviour of our exact widgets, Safari 7-day storage rule on the real phone (the WebKit page does not mention it), JAWS free path, Base UI/Ariakit exact React peer ranges.
7. Minor: report's "ARIA tabs for scope chips" warning does not apply (our palette has no tab roles); report said duplicate step number 2.20 in the plan: true, now renumbered.

## 3. Decisions adopted (what changes in the master plan)
1. **Plan hierarchy (4.3): nested ordered lists + disclosure buttons + native checkboxes for leaf steps; no ARIA tree/treegrid in v1.** Status (blocked/deferred/cancelled) is visible text next to the checkbox, never a checkbox state; progress text "8 of 12 countable steps complete; 2 blocked", optionally `<progress>`.
2. **Behaviour layer**: keep our animated look; run a 2-day spike of React Aria (Select, Menu, ComboBox/ListBox) on the invite dropdown and the palette, adopt only if it passes our animations, native `<dialog>` and a physical Android TalkBack test. Base UI and Ariakit = assess, Radix = hold. Our Select already follows the APG select-only model (see 4), so the spike is a risk check, not a rewrite.
3. **Org tabs become route-backed** (`#/org/<id>/people` etc., links with `aria-current="page"`): fixes deep links, Back, and the broken partial tab semantics in one change. Same for the "Organizations" active/deleted switch.
4. **Diff review (5.7)**: keep `@codemirror/merge` for the visual diff, add a linear "Changes" list (hunk n of m, old/new text, native Accept/Reject buttons with context names). Do not claim the merge view is accessible until a real AT session proves it.
5. **Reorder (5.4)**: drag plus Move up / Move down / Move to in each item menu (WCAG 2.5.7), shipped together.
6. **Offline (8.3)**: explicit "Available offline on this device" pins, read-only; shell service worker (vite-plugin-pwa 2.0.0 / Workbox 7.4.1) stays registered; private IndexedDB wiped on sign-out; "Forget this device" also unregisters; never runtime-cache authenticated responses; no WebCrypto encryption of IndexedDB in v1; no offline edits; Background Sync not used.
7. **Performance budgets** (engineering policy, not standards): initial JS 180 KiB compressed target (220 KiB hard review), CSS 40 KiB, 30 requests, LCP 2.0 s, INP 150 ms, CLS 0.05 on a mid-range Android; split CodeMirror, merge, Markdown extras, import worker, labs, answer engine; virtualize only after measuring (about 300-500 rows is a profiling checkpoint). Keep Vite's default target.
8. **Testing**: Vitest 5, Playwright 1.64.1 (traces on first retry), ARIA snapshots and axe at every widget state, pinned axe version, a small visual-regression set NOW (10-20 screenshots; reverses my "deferred" 2.27), pgTAP in the local stack, Chromium PR job + Firefox/WebKit nightly, physical-device AT matrix (NVDA, Narrator, TalkBack, iPhone VoiceOver) as release gate, flake = retry-success recorded as flaky, coverage floor 70/65 with about 90% branch on pure security/version/import logic (policy, not standard), mutation testing on hold.
9. **Lint stack (9.1): Oxlint (MIT, 1.89.0, native TS/JSX, includes jsx-a11y rules and react `exhaustive-deps`; `rules-of-hooks` exists but is opt-in "pedantic") + `tsc` from TS 7 for types. Revisit ESLint 10 + typescript-eslint after it supports TS 7.1.** Rule sets to enable are TRIAL: verify on our code. Biome 2.6.2 is the alternative (a11y/hooks rule coverage not verified here).
10. **Error + RUM (9.8)**: first-party `client_error_events` (release, route template, sanitized fingerprint, coarse browser) and a `web-vitals` RUM table (route template, release, metric, value, device class; 30 days; no ids, titles, queries, hashes, secrets). Sentry/GlitchTip on hold (terms unverified). Speed Insights optional only as a rough score.
11. **Browser baseline (Q21 recommendation: yes)**: current + previous Chrome/Edge/Firefox/Safari including iOS Safari; keep Vite's default target; adopt dialog, popover (selectively), `:has()`, container queries, `color-mix()`; trial `@starting-style`, View Transitions; hold anchor positioning, scroll-driven animation, Temporal and customizable `<select>` as dependencies.
12. **Auth screens (3.13/3.14)**: one OTP field with `autocomplete="one-time-code"` and paste, `new-password`/`current-password` autocomplete, paste never blocked, manual TOTP seed plus QR, Turnstile test keys in CI and a documented fallback, second TOTP factor before enforcing AAL2. Passkeys: assess only (Supabase marks them experimental).
13. **Assistant rules (AGENTS.md)**: bounded changes with acceptance tests; no package installed until the owner verifies registry name, maintainer, age, licence and need; no unreviewed migrations, security policy or deploys; no secrets, dumps or share links in prompts.

## 4. Audit of OUR code against the report (new, from `parts/*.tsx` and the CSS tokens)
**Already good (keep):** native `<dialog>` with `showModal()` in 5 dialogs (form modal, confirm, import, palette, settings); popups are portalled INTO the nearest open dialog (`popHost`), which avoids the top-layer/popover pitfall the report warns about; custom Select is a select-only combobox (`role=combobox`, `aria-activedescendant`, `aria-controls`, Home/End, typeahead, Escape keeps the value, active option scrolled into view); menus use `menuitem` buttons; motion setting (system or forced) drives `data-motion`; toast is `role=status` and pauses on hover; the views I checked have an `<h1>`; `nav` landmarks have labels; segmented controls use `aria-pressed`; diff has a `forced-colors` rule; native focus ring `2px solid #6da8ff` (7.0:1) on `:focus-visible`; palette scopes are not tabs; text tokens pass (see below).
**Problems found:**
1. **Org tabs** (`parts/49-orgs.tsx` lines 231, 369): `role=tablist/tab` with `aria-selected` only: no roving tabindex, no arrow keys, no `aria-controls`/`tabpanel`, state-only. Every tab is a Tab stop and arrows do nothing: worse than plain buttons. Fix = route-backed links (decision 3).
2. **No skip link, no per-route `document.title`, no focus/announcement on route change** (title is only touched for the unread-count prefix; `hashchange` handler does not move focus). One `<main>` exists.
3. **Control borders fail 1.4.11 where the border is the only identifier**: `--line` #2a2926 and `--line2` #3b3a35 give only 1.04-1.62:1 against our surfaces (needs 3:1). Applies to text inputs, textareas, search fields (placeholder alone is weak). Buttons and selects with text/icons are exempt. Candidate control-border token `--ctl-line: #77756c` = 3.99:1 on `--bg`, 3.88 on `#181715` (textarea fill), 3.69 on `--raise`, 3.28 on `--bubble`; check on `--hover`/`--active` before adopting.
4. **Select**: `aria-controls` points at the inner wrapper `div` (`${id}-l`) that has no role; the `role="listbox"` is on the `.pop` element. Put id and role on the same element. Tab currently closes without committing the active option (APG commits): decide and test, minor.
5. **forced-colors** handled only for the AI diff; no global pass (borders as the only state cue, selected/active rows, focus ring) yet.
6. **Contrast of accent**: `--acc` text on `--active` is 4.48:1 (just under 4.5); primary button text #141413 on `--accb` is 4.73:1 (passes). `--tx4` on `--active` 4.90 passes. All other text/semantic tokens pass on every surface (`--tx3` 6.1-8.1, `--blue` 5.2-6.9, `--ok` 7.8-10.3, `--bad` 5.8-7.6, `--warn` 7.3-9.7, `--focus` 5.8-7.6).
7. **Hit areas**: avatar 26 px and dense `.btn` 26 px pass; `.nav-n` 20 px is a non-interactive badge. I did not measure every icon button: add a Playwright geometry test that fails any visible interactive element under 24x24 without the spacing exception.
8. **No linter exists** (no ESLint/Oxlint config): adding Oxlint is the cheapest accessibility gain (static `jsx-a11y` checks).
9. Plan items already numbered twice (`2.20`): second one renumbered 2.20b.
