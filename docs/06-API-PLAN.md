# API and integration plan

Rule: keys never go in chat, code or git. Storage: Supabase Edge Function secrets (dashboard dialog or `create_edge_function_secret` tool which opens a dialog). Browser never sees them; every call goes through an Edge Function that checks the signed-in user and rate-limits.

| Priority | Integration | Use | Notes |
|---|---|---|---|
| 1 | OpenRouter (several keys as ONE secret `OPENROUTER_KEYS`, comma list) | ask-the-docs, summaries, "why this changed", draft step text | free models churn and are capped (~50/day without credit, third-party report, UNVERIFIED): discover models at runtime, never hard-code a `:free` id; verbatim quote check on every answer |
| 2 | GitHub REST/GraphQL (fine-grained token, repo-scoped) | link phases/steps to issues & PRs, push Markdown export to a repo, status badges | read-only first |
| 3 | Supabase Storage | file attachments per project (PDF, images), signed URLs | RLS on storage.objects |
| 4 | Resend / SMTP | digest of pending AI edits, token-expiry mails | one Edge Function, opt-in |
| 5 | Web Push (VAPID, no third party) | "new AI edit waiting" notification | service worker |
| 6 | Vercel API | show deploy status in the app | read-only token |
| 7 | Cloudflare Turnstile | protect public forms/signup | |
| 8 | Embeddings (pgvector is available in the project) | semantic search | model via OpenRouter or Supabase AI inference (UNVERIFIED availability) |
| 9 | Calendar (ICS feed generated by an Edge Function) | phase due dates in any calendar app | no OAuth needed |
| 10 | Webhooks out (signed) | notify other systems when a decision is made | HMAC header |
