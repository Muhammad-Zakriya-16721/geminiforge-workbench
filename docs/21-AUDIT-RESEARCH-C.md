# Audit of the ChatGPT Deep Research report, Part C: security and privacy (2026-10-22)
Raw report: `21a-RESEARCH-C-CHATGPT-RAW.md` (15k words; its 70-item security test pack and 37-item malicious-input corpus M01-M37 live there and are the test source). Audited by Claude against primary docs, npm, the live site, the live database and the full git history. Verdict: good report; its design is sound; several of its "2026 facts" were wrong or unconfirmed.

## Verified TRUE
- Supabase Auth (docs): TOTP app-authenticator MFA exists; `aal` claim in the JWT; RLS pattern `(select auth.jwt()->>'aal') = 'aal2'` (docs recommend `as restrictive` policies). Sessions last indefinitely by default with unlimited sessions; time-box, inactivity timeout and single-session are **Pro-only** (docs). Refresh-token reuse detection exists (10 s reuse interval). Passkeys are **experimental** (needs supabase-js >= 2.105.0). CAPTCHA supports hCaptcha and Cloudflare Turnstile. The default SMTP is best-effort, non-production and rate limited ("can change without notice"). Supabase account MFA: no recovery codes, register a backup TOTP factor (that page is about dashboard accounts; project-user recovery codes still UNVERIFIED).
- Incidents (searches, several sources): Axios npm compromise 2026-03-31 (hijacked maintainer, versions 1.14.1 and 0.30.4, fake dependency `plain-crypto-js@4.2.1` with a postinstall RAT, live about 3 h); Shai-Hulud npm worm 2025-09 and Shai-Hulud 2.0 2025-11; GitHub's npm hardening plan after the first wave. Mammoth CVE-2025-11849 (GHSA-rmjr-87wv-gf87, published 2025-10-17, critical 9.3, fixed in 1.11.0). Confluence CVE-2023-22515/22518 are real.
- npm `min-release-age` (days) exists since npm 11.10.0 (two secondary sources). Push protection and secret scanning are free on public repos (GitHub blog); no historical scan in the free push protection.
- Fragment principle: a URL fragment is not sent in the HTTP request and is excluded from Referer (MDN, Referrer Policy spec); it does NOT protect against history, extensions, screenshots or JS reading `location`.
## WRONG or UNVERIFIED in the report (do not rely)
- WRONG (not confirmed, contradicts docs): "Vercel made production deployment protection free on all plans in September 2026". Vercel's docs say Vercel Authentication covers preview/deployment URLs on Hobby; protecting the production domain needs Pro. Do not plan on it.
- UNVERIFIED: Mammoth prototype-pollution (fixed 1.12.2) and ReDoS (fixed 1.12.3) advisories (not found); npm shows mammoth 1.12.1-1.12.3 and 1.13.0 (2026-09-26) exist. Policy: pin the latest release, recheck advisories before install, sandbox anyway. `allow-scripts` npm option: not found. Microsoft Safe Links behaviour on fragment pages. Gmail app-password daily limit (the old "500/day" is unverified; never rely on it). Notion/Google Docs/BookStack/GitHub leak case studies (no primary source).
- Over-specific: HSTS. Vercel ALREADY sends `strict-transport-security: max-age=63072000; includeSubDomains; preload` on the live site: do not set HSTS in vercel.json. Live site also sends `access-control-allow-origin: *` on static files; `/share` returns 404 today; index.html contains a `<style>` tag.
- CodeQL on public repos: the GitHub page only says private repos need a Code Security license; public availability is implied, not stated: check Settings > Code security.

## Design adopted into the master plan (audit recommendations, owner OK pending where marked Q)
1. Share link = `https://<app>/share#<43-char base64url secret>` (not `/#/s/...`): Vercel rewrite `/share` to index.html so headers/robots can differ; first paint shows nothing; explicit "Open shared project" click; POST the secret in the body; `history.replaceState` to `/share`; content only in memory; no analytics/third parties/service-worker caching on that page.
2. Redemption through a SERVER proxy (Vercel function with `sb_secret_` in a server env var, SQL function executable only by service_role). Reject: anonymous SECURITY DEFINER RPC (needs anon API execute) and share-viewer JWTs. `Cache-Control: no-store`; revocation checked on every fetch; global kill switch; pseudonymous short-lived rate bucket, no raw IP log.
3. Several independent project-wide links (labelled, read-only, default 7 days, no never-expire). Store only SHA-256 of 32 random bytes; slow hashes and homemade constant-time compare are not needed (indexed digest lookup). The SQL must use `extensions.digest` under an empty search_path.
4. Public projection allowlist: project name/description; documents (opaque key, title, current body, order); plan (title, hierarchy, status). Everything else excluded (members, emails, ids, revisions, review inbox, drafts, Trash, comments, tokens, audit, notifications, search tables, Storage, Realtime, exports). No Storage images in v1 shares.
5. Auth: public sign-up OFF; invite-bound account creation through `/api/join` using `auth.admin.createUser(email_confirm:true)` with a server key; existing accounts must sign in first; Turnstile on that endpoint; generic errors; password minimum 15 (NIST 800-63B-4, single factor); TOTP for owner/admin; AAL2 required inside sensitive RPCs; magic links not the primary flow; passkeys later.
6. Browser hardening: move the inline CSS string and the `<style>` in index.html to a real CSS file; drop Google Fonts (system stack or self-hosted); `vercel.json` with CSP in Report-Only first (default-src 'none'; script-src 'self'; style-src 'self'; connect-src self + Supabase https/wss; img-src self blob: Supabase; frame-ancestors 'none'; base-uri/object-src none), global Referrer-Policy no-referrer, nosniff, X-Frame-Options, Permissions-Policy, COOP/CORP same-origin, global X-Robots-Tag noindex, `/share` no-store, hashed assets immutable. NOT HSTS. Skip a public CSP-report endpoint in v1 (extra anonymous surface): catch violations in Playwright. zip.js workers may need `worker-src 'self' blob:`.
7. Untrusted content: no raw HTML, no remote images in review/share, URL allowlist https/mailto/#/internal, `user-content-` id prefix, no SVG upload, YAML front matter allowlist (no custom tags/aliases, reject `__proto__`/`constructor`), CSV neutralisation, ZIP import first (`@zip.js/zip.js` 2.24.0 or fflate 0.8.3 pinned) in a Worker with caps (25 MiB archive, 100 MiB emitted, 10 MiB entry, 1000 entries, ratio 100:1, depth 20, reject symlinks/absolute/`..`/NUL/reserved names/case collisions); `.docx`, Notion zip deferred (Mammoth latest + Worker + external access disabled).
8. Repo/CI: Actions pinned by full SHA, `permissions: contents: read`, no `pull_request_target` with untrusted code, gitleaks (+ custom `sb_secret_` rule), osv-scanner, `npm ci`, `npm audit --omit=dev`, Dependabot with cooldown, npm `min-release-age=7`, try `npm ci --ignore-scripts`, no server secrets in the build environment, GitHub secret scanning + push protection + Dependabot + code scanning where available, ruleset requiring CI, private vulnerability reporting.
9. Privacy: delete the duplicate invite email after the invite is resolved (hashing is not deletion); pseudonymise authors on user deletion; invitation preview reveals nothing to unauthenticated visitors; bounded retention for security events.
10. Audit: small append-only `private.security_audit_log` (reject UPDATE/DELETE by trigger, no grants), security events only; no hash chain now; pgaudit only for investigations; Vercel Hobby runtime logs are about 1 hour.
11. Abuse/invites: `/api/invite` requires auth + AAL2 + an existing invite row, recipient and body derived server-side; quotas 3/hour and 10/day per org, 3/day per recipient (policy, replaces 20/60); owner kill switch table `private.security_settings`.
12. Runbook for the sole owner (credential inventory, share-link kill, secret rotation, account recovery, compromised GitHub/Vercel/Supabase/Google) before public sharing ships.
